## 3. 为什么一次失败会等待很久

当前 LLM 配置：

- host：`www.autodl.art`
- base path：`/api/v1`
- model：`qwen3.6-plus`
- API Key：已配置（本文不记录密钥）。

`LLMClient` 当前参数：

- 单次请求超时：90 秒。
- 最大重试：2 次，即最多发起 3 次请求。
- 一次完整失败理论上可能等待约 270 秒，加上退避时间约 4 分 34 秒。

事件生产至少包含多个串行 LLM 调用。根据时间推断：事件规划调用约等待一个完整重试周期后成功，随后首章或下一阶段调用又等待一个完整重试周期并失败，因此总耗时接近 10 分钟。

轻量连通性检查显示 `www.autodl.art/api/v1/models` 在约 0.45 秒内返回 HTTP 404，说明当前基础 HTTPS 连接可达，但该兼容接口不提供 `/models` 路由；这不能证明 `/chat/completions` 当前稳定。实际生产错误仍指向上游模型接口或代理链路不稳定。

## 4. 本轮已经完成的主要修改

### 4.1 章节字数策略

- 硬范围改为 2500～2800 字。
- 最多尝试修正 3 次。
- 三次仍不达标时，选择所有候选中距离硬范围最近的版本，并结束字数修订，防止无限循环。

### 4.2 段落长度策略

- 优先在句号等自然句末处分段，不重新生成段落内容。
- 最好低于 60 字。
- 每章超过 60 字的段落不超过 3 段。
- 每章超过 80 字的段落不超过 1 段。
- 单段最长不超过 120 字。

### 4.3 事件级审校与批量修订

- 不再逐章、逐问题无限循环修订。
- 一个完整事件生成后执行事件级审校。
- 同一章中互不冲突的问题合并为修订包，一次修改后整体验收。
- 修订轮数受限，仍有高风险问题时暂停，交给用户决定。

### 4.4 测试事件续跑

- 修复字数暂停后完成第 6～8 章却未写入 `test_run_event_completed` 的问题。
- 避免继续按钮误创建额外测试事件。
- 修复“字数修正”和“首章质量修正”共用错误按钮文案的问题。

### 4.5 时间线与结构化起始需求

- 增加 `TimelineEntry` 时间线管理。
- 起始需求包含故事年代和地点，并进入章节生成约束。
- 人物设定结构化，支持增删人物及姓名、性别、年龄、职业、是否主角等字段。
- 创建作品时不要求用户预设剧情事件；事件由系统规划。

### 4.6 资料检索修复

此前系统只要存在故事年代，就会自动执行两组宽泛查询，把完整年代、地点说明与“日常生活、科技、通信、交通、职业制度、常用物品”等分类词拼接，导致 Tavily 返回大量无关新闻和网页垃圾。

已修改为：

- 年代和地点仍是生成硬约束，但不再自动触发宽泛检索。
- 只有具体剧情动作确实依赖现实知识时才检索。
- 每个事件最多 3 个具体查询。
- 每个查询最多保留 3 条来源。
- Tavily 最低相关度为 0.45。
- 增加登录注册、网页抓取模板、低质量域名等过滤。
- API 展示、缓存复用和章节上下文分别执行过滤，旧垃圾来源 ID 也不能进入生成提示词。
- 已为当时检查的作品清除 10 条低相关来源，并同步清空事件内保存的来源 ID。
