# NovelForge 协同样本标注平台最终实施方案

> 状态：最终执行基线  
> 日期：2026-08-03  
> 原则：复用现有基础设施，不并行维护同类组件；模型只做总体分析，精彩片段由用户协同标注产生。

## 1. 产品目标

把现有“样本分析”改造成公共与私人并存的协同标注平台：

1. 用户上传 TXT/MD 小说后，原文保存在 MinIO。
2. 大模型只输出三类内容：总体评价、语言表达原则、应避免的错误。
3. 用户可以在原文中选择连续文本并添加多个分类标签。
4. 公共作品允许其他用户阅读、标注、投票和举报；私人作品仅上传者可见。
5. 多人标注互不覆盖，系统将独立观点聚合成可信结果。
6. 只有可信、授权且与当前写作任务相关的标注才能进入生成上下文。

不再让模型自动筛选所谓“精彩原句”，也不再自动生成大量剧情经验卡和表达经验卡。

## 2. 最终技术栈

| 能力 | 最终实现 |
| --- | --- |
| 前端 | 现有 Next.js + React |
| API | 现有 FastAPI + Pydantic |
| ORM与迁移 | 现有 SQLAlchemy + Alembic |
| 业务、审计、权限 | 现有 PostgreSQL 16 |
| 向量与关键词检索 | 现有 pgvector；PostgreSQL 内启用 pg_trgm |
| 原文与分段文本 | 现有 MinIO，不接入 AWS S3 |
| 后台任务 | 现有 Redis + Worker + LangGraph，不引入 Celery、Kafka、RabbitMQ |
| 实时通知 | HTTP 写入；FastAPI SSE + Redis 通知；数据库事件负责断线补拉 |
| Embedding | 现有百炼 `qwen3.7-text-embedding`，固定 1536 维 |
| 登录鉴权 | 现有 JWT + bcrypt |
| 防刷限流 | 复用 Redis 计数器；数据库保存最终状态 |

## 3. 数据边界

### 3.1 MinIO

- 原始文件使用用户、样本ID和安全文件名组成对象Key。
- 分段阅读文本保存在同一套 MinIO 的受控前缀中，PostgreSQL 只保存对象Key、字符偏移与哈希。
- 所有读取都经过 FastAPI 权限校验，不向浏览器暴露 MinIO 凭据。
- 删除私人作品时同步删除原文和分段对象；已公开并产生社区标注的作品改为下架，不物理级联删除公共贡献。

### 3.2 PostgreSQL

继续复用 `sample_analyses` 作为样本作品表，并新增：

- 可见性、发布状态、复用许可、权利声明、内容哈希和乐观锁版本。
- `sample_text_segments`：MinIO 分段对象的顺序、字符偏移和哈希。
- `sample_annotations`：选区、原句快照、多分类、说明、可信状态、向量和版本。
- `sample_annotation_revisions`：修改前快照，形成追加式审计记录。
- `sample_annotation_votes`：每个用户对每条标注只能保留一个有效投票。
- `sample_annotation_reports`：举报原因与处理状态。
- `sample_user_reputations`：可信贡献数、被拒数、信誉分。

## 4. 权限与公共/私人隔离

1. `private`：仅所有者可读、可标注、可用于自己的作品。
2. `public`：只有 `publication_status=published` 才能被其他登录用户读取和标注。
3. 上传者选择公开时必须提交权利声明和复用许可。
4. 每个查询统一经过“所有者或已发布公共作品”条件，禁止前端自行拼接权限。
5. 标注的向量检索同时校验作品可见性、标注可信状态和复用许可。
6. 私有标注不会因投票或索引进入公共结果。

## 5. 协同冲突处理

- 不允许多人覆盖同一标注。不同用户对同一段落的结论各自保存。
- 选区重合度只用于聚合展示，不用于合并或删除原始贡献。
- 用户修改自己的标注时必须提交 `version`；版本不匹配返回 HTTP 409，并保留旧版本。
- 分类可以多选。系统按“作品、重叠选区、分类”形成聚合视图，展示支持人数和分歧，而不是强行给出唯一答案。

## 6. 反污染与可信度

### 6.1 写入前规则

- 选区必须来自服务端保存的原文分段，客户端提交的引文必须与偏移对应。
- 选区长度限制为 2—1000 字；说明限制为 500 字。
- 分类必须来自系统枚举。
- 禁止给自己的标注投票；同一用户对同一标注只能有一个投票。
- 重复选区、重复内容和异常频率由数据库约束及 Redis 限流拦截。

### 6.2 可信状态

- 私有标注：创建后即为 `trusted_private`，只供本人使用。
- 公共标注：初始为 `pending`。
- 公共标注至少获得两个不同用户的有效支持，且加权可信度达到阈值后进入 `trusted`。
- 举报或反对达到阈值时进入 `quarantined`，立即退出生成检索。
- 信誉只影响聚合权重，不允许高信誉用户直接覆盖他人记录。

### 6.3 信誉更新

- 初始信誉为 1.0，范围固定在 0.2—2.0。
- 标注被社区确认后小幅增加；被确认无意义、伪造或恶意污染后降低。
- 新账号、短期高频账号和高度重复贡献有更低的有效权重。

## 7. 标注分类

系统固定使用以下分类，不允许用户自行创建同义类别：

- `humor`：幽默与笑点
- `internet_meme`：网络热梗
- `abstract`：抽象表达
- `characterization`：人物塑造
- `dialogue`：人物对话
- `inner_voice`：心理活动
- `environment`：环境描写
- `foreshadowing`：伏笔
- `hook`：开篇或章尾钩子
- `pacing`：节奏与转折

## 8. AI分析契约

样本分析任务只返回：

```json
{
  "overall_evaluation": "总体评价",
  "language_principles": ["语言表达原则"],
  "avoid_errors": ["应避免的错误"]
}
```

- 不输出剧情经验卡。
- 不输出自动挑选的精彩原句。
- 不直接把全量统计指标展示给用户。
- 模型不可用时保留样本与分段阅读能力，报告标记为待重试，不删除用户数据。

## 9. 标注索引与生成使用

1. 新标注或修改后的内容按内容哈希去重。
2. 私有可信标注立即进入私人索引；公共标注达到 `trusted` 后才建立向量。
3. 投票只更新可信度，不重复生成向量。
4. 修改选区、分类或说明后，标注版本递增并异步重建该条向量。
5. 检索使用 pgvector 语义召回与 pg_trgm 关键词召回，通过 RRF 合并。
6. 生成时最多注入少量高相关标注，并附带分类、适用边界和是否允许原句复用。
7. `reference_only` 只允许学习表达机制；只有明确授权的 `excerpt_reuse` 才允许原句进入可直接引用候选。
8. 输出仍需通过重复度检查，防止连续复制样本内容。

## 10. API范围

- 我的样本：上传、列表、重新分析、调整公开状态、下架或删除。
- 公共空间：分页搜索已发布作品。
- 阅读器：分页读取MinIO分段内容与字符偏移。
- 标注：创建、修改、删除、列表和聚合统计。
- 治理：投票、举报、可信状态重算。
- 索引：通过现有Worker执行单条标注Embedding，不在HTTP请求中等待远程模型。

## 11. 前端范围

样本页面改为三个区域：

1. **公共样本**：搜索、查看作品和社区标注。
2. **我的样本**：上传、查看分析、控制公开状态和删除。
3. **标注工作台**：左侧原文阅读器，右侧显示当前选区、分类多选、说明、社区标注与投票。

默认不把AI说明或技术细节堆在列表页；用户展开作品后才看到三项分析结果。

## 12. 实时与可靠性

- 标注写入仍走普通HTTP事务。
- 实时变化通过SSE通知，事件带递增序号。
- Redis只负责唤醒与广播；PostgreSQL是事实源。
- SSE断线后客户端使用最后事件序号补拉，空白心跳不算业务事件。
- Embedding任务使用现有任务租约、心跳和崩溃恢复机制。

## 13. 实施顺序

1. 数据库迁移和模型。
2. 权限、原文分段、标注、投票和举报API。
3. 简化 SampleAnalysisAgent 输出契约。
4. Worker分段任务与单条标注索引任务。
5. 可信标注RAG接入。
6. 公共空间、我的样本和标注工作台前端。
7. 后端测试、Alembic升级、前端构建和回归验证。

## 14. 验收标准

- 私人样本无法被其他用户通过列表、ID枚举或阅读接口获取。
- 公共样本可以被其他登录用户阅读和独立标注。
- 同一段落的不同标注可以共存，不发生覆盖。
- 标注修改发生版本冲突时返回409。
- 无意义、越界、伪造选区和重复投票被拒绝。
- 未达到可信阈值的公共标注不会进入生成检索。
- 大模型报告只包含总体评价、语言表达原则和应避免错误。
- 原文与分段仍存储在MinIO；数据库不保存整本原文。
- 百炼Embedding失败不会阻塞标注保存，任务可恢复重试。
- API测试通过，前端生产构建通过。
